## Findings
1. **`infer.accumulate_device=auto` falls back to CPU accumulation from the second tomogram on**
   (both CZII and filaments: 13 → 5 patch batches/s). Forcing `cuda`: both tomograms at ~12.7 it/s,
   2.3× faster predict. Hits every multi-tomogram predict and every calibration. Likely cause: the
   decision uses `torch.cuda.mem_get_info`, which does not count memory held by PyTorch's caching
   allocator. → 8e.1 (first item).
2. Predict is the patch loop: ~25 patches/s at batch 2 (one forward of 16 training patches with
   backward takes 1.2 s; eval forward of 2 patches should be ~20-30 ms, the loop runs ~75 ms per
   batch). Batch size, GPU-side patching and accumulation → 8e.1.
3. Calibration: the greedy NMS loop at the lowest threshold costs 20 % of CZII calibration; filament
   threshold tracing 22 % of filament calibration. → 8e.1.
4. Training is GPU-bound and ≈ 97 % network + loss; loader keeps up today. 8b order stays.
5. Chunking time is negligible (65 s against 4.3 h per fold); the case for on-the-fly crops (8c) is
   disk (8.7 GB per fold), the C = 134 data path, and the GPU augmentation head-room — not chunking time.
6. Handoff quoted 23.7 s per filament tomogram; measured here 98 s on the 3c.2 validation tomograms
   (`10490_sample_6/7`, 6.8 Å/px). The difference is not explained yet (other tomogram sizes, or the
   accumulator fallback); re-check in 8e.1.
