## Predict and calibration (`benchmarks.perf.pipeline`; 2 validation tomograms each) — corrected 9 Nov 2026
The first version of this table was measured with `--profile` (cProfile) on the timed runs and not on
the warm-up; cProfile slows the Python patch loop ~4x, which also produced a false "accumulator falls
back to CPU" finding. Re-measured without the profiler (`run_pipeline.sh` no longer passes it):

| Stage | wall | per tomogram | where |
|---|---|---|---|
| CZII predict (6 classes, batch 2, no TTA) | 136 s | 68 s | `_predict_level` 128 s; MRC load 5 s; peaks 1.5 s |
| Filament predict (2 classes) | 84 s | 42 s | `_predict_level` 77 s; tracing 3.6 s |
| CZII post-fit calibration | 231 s | 115 s | predict 135 s; **`peak_local_max_torch` 80 s (35 %)** |
| Filament calibration | 126 s | 63 s | predict 81 s; **threshold tracing 43 s (34 %)** |
| CZII chunking (7 tomograms, pipeline v2, fold 0) | 65 s | — | 8957 volume chunks, 8.7 GB |

Run-to-run spread of CZII predict: 36-68 s per tomogram on the same code and GPU (patch loop at 12.8
to 22 batches/s; the loop is bound by CPU work per patch — TorchIO sampling, per-patch accumulation —
and sensitive to host load). Old and new `accumulate_device=auto` rules both choose the GPU here and
give identical picks.

## Findings
1. ~~`accumulate_device=auto` falls back to CPU from the second tomogram~~ — **withdrawn**: a cProfile
   artefact (see above). The rule now also counts the allocator cache as free (8e.1, tested), which
   matters only when little GPU memory is left; no speed-up measured.
2. Predict is the patch loop: 13-22 patch batches/s at batch 2, CPU-bound and noisy. GPU-side patch
   grid, larger batch and batched accumulation → 8e.1.
3. Calibration: the greedy NMS loop costs 35 % of CZII calibration; filament threshold tracing 34 % of
   filament calibration → 8e.1.
4. Training is GPU-bound and ≈ 97 % network + loss; loader keeps up today. 8b order stays.
5. Chunking time is negligible (65 s against 4.3 h per fold); the case for on-the-fly crops (8c) is
   disk (8.7 GB per fold), the C = 134 data path, and the GPU augmentation head-room — not chunking time.
6. Filament predict: 42 s per tomogram here vs 23.7 s quoted in the handoff (other tomograms / host
   load); the 98 s of the first version was the profiler.
